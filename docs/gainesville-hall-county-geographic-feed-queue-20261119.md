## Start here every run

1. Read the original ledger and this queue, then use **read-only** `public.municipal_event_sources` to re-deduplicate exact URLs/domain + source keys. Do a **fast, wide** publisher search in all nine families and every priority subarea, insert a batch of leads *before* spending the whole run debugging one publisher. Identify replacement publishers in the same geography when blocked.
2. Work the top ready candidates sequentially with concurrent independent investigation where helpful: check publisher robots/policy, current first-party endpoint/data, future local clock and recurrence/year, canonical per-event URL, **event-specific** address, category, complete available description, image provenance, and duplicate/event overlap. Don't invent field values or reinterpret website post dates as event starts. "Publisher page found" is NOT "source validated".
3. When a source passes real collector preview, implement/test/merge a focused `roomquestgame/community-calendar` PR, deploy its **exact merged SHA** to `roomquest-community-collector` production Vercel, confirm READY, then create ONE new safe forward DB migration per coherent registration batch in `roomquestgame/RoomQuestGame` via protected `db-deploy.yml`. **Never direct-write production Supabase or touch/replay PG17 squash.** Release 1 feed if only 1 validates. Re-read migrations/main and drift.
4. Check read-only staging and non-hidden public `external_events` before calling anything released, and audit **distinct geo points** and coverage by town—not just event count. Move immediately to the next lead, regardless of 20-count or a blocked source.
5. Update this queue with explicit `discovered | validating | held:<reason> | collector-merged-READY:<SHA> | DB-registered | staged:<n> | public:<n>` and a **next executable step**. An hourly wake-up resumes at that step, not from scratch.
