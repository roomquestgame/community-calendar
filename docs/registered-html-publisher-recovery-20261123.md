## Publisher evidence and parser contracts
**Cambridge Corn Exchange** `https://www.cornex.co.uk/events`: source robots.txt returned HTTP 404 (absent policy). Its public HTML has a canonical unfiltered `/events`, a numbered pagination control with the current page shown as a non-link span, and a linked second page `?page=2`. First observed page had 24 unique publisher event details and page 2 had several more. Event-detail JSON-LD includes Schema.org Event title, first date and UK PostalAddress but often **no event URL nor start clock**; the canonical detail page has an exactly agreeing H1, date and `.event-details__item--time dd` clock. For GB/UK, resolve the local clock with `Europe/London`, refusing nonexistent/ambiguous DST transitions. If published date spans a range, use **only** the JSON-LD first day when an unambiguous clock exists; never create extra day occurrences. If the publisher says **“Times vary by date”**, the detail produces no fabricated event. Explicit merchandise-only add-ons are not events. Expanded the bounded complete-list detail cap from 20 to 40, retained 3-page and deadline limits, and still refuses partial paginated snapshots. An end-to-end live replay fetched both pages and every detail, returning 24 timestamped records before the merchandise-only exclusion; no public database write was made during replay.

**Commonwealth Brewing** `https://commonwealthbrewingcompany.com/events/`: robots.txt returned HTTP 200 with Disallow only `/wp/wp-admin/`. Its CMS publishes a FacetWP event index, not a WordPress `wp/v2/event` or TEC REST feed. The actual `FWP_JSON.preload_data.settings.pager` declared **page 1 of 1, 3 total rows**, matching three rendered cards. Collector now accepts an otherwise-empty FacetWP pager as complete **only** when this publisher preload asserts exactly one page and the visible event-card count matches its total; multi-page/contradictory preloads stay held. Two individual publisher event details have unique title headings, permalink dates agreeing with day/month and printed start/end clocks, a linked specific taproom and matching **official venue footer postal address** in Virginia. This tight native-card parser uses `America/New_York` only with matching VA address and the existing canonical URL/registered native evidence. The third `GMU COME THRU` listing spans October–May and cannot establish individual dated occurrences; it produces no fabricated event. An end-to-end live replay returned **two** dated market events (Fairfax and Virginia Beach). The WordPress site's custom event type did not expose a public REST calendar.
