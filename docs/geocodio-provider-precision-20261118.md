# Geocodio provider-coordinate acceptance — November 18, 2026

**Owner decision:** accept the provider's top valid coordinate for first-party, source-verified event addresses. The former strict accuracy >= 0.90 + rooftop/point-only gate is replaced by ranked-provider output from these tiers: rooftop, point, range_interpolation, nearest_rooftop_match, intersection, street_center, and city/place. Never manufacture coordinates.

Collector code `roomquest/forward_geocoder.py`: retain the original source venue street address, Geocodio v2 response accuracy and accuracy_type, and choose the top-ranked valid result. The collector verifies U.S. country, state, plausible matching street/building or matching city for a coarse Geocodio place; no guessed venue/default from publisher address; malformed coordinates, other-state results and county/state centroids fail. Omitted suites at an otherwise verified building no longer block the publisher's point. Do not reject a valid first result because a lower-ranked alternative differs.

Matching database change lives in roomquestgame/RoomQuestGame, migration `20261121180000_geocodio_provider_precision_acceptance.sql`, branch `fix/geocodio-trust-provider-coordinates-20261118`. It must deploy via protected GitHub db-deploy.yml **before** a collector production deployment. It retains all token/reservation/lease/usage-cap controls, stores accuracy and precision evidence, and reopens only two exact, one-attempt ambiguous Santa Cruz brewery address identities (Woodhouse ID 5797 and Discretion ID 5798). Existing rejected raw responses were not retained, so fresh normal worker attempts are needed to establish coordinates.
