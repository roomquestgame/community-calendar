## Mandatory processing / release protocol

- **Discover source first**. Prefer first-party structured Events Calendar REST, JSON-LD, JSON or documented APIs; then ICS/RSS; only finally deadline-bounded HTML with robots, crawl-delay and exact allowlist. No scraping through 403/CAPTCHA/Cloudflare, no stale archived calendars, no paid provider assumed.
- For each eligible original occurrence, keep exact **start/end America/Los_Angeles wall time** or verified UTC offset, real publisher recurring instances (no invented repeat dates), the *complete non-placeholder description*, actual event URL and publisher category clues. Reject cancelled, private, undated and ambiguous event records.
- Venue names without full streets must be matched against official named-venue addresses and the existing venue alias/address cache. On unknown or conflicting street, hold for review; confirmed address enters shared Geocodio queue and precision-qualified coordinate cache. Use verified publisher GEO when truly event-specific. Never copy source coverage center as a venue coordinate or synthesize coordinates.
- Images are publisher-linked **candidates** subject to existing rights, source identity, byte-size and downstream media gates. Retain source evidence; no unauthorized image rights assertion.
- Only advance batch count after an isolated **guarded live `preview_worker.preview_source`** of a newly implemented collector, focused regression tests and identity checks. Once **20** independent new feeds qualify, group into coherent PR(s), merge tests, confirm Vercel production READY, then one protected, forward-only source-enrollment migration via `RoomQuestGame/.github/workflows/db-deploy.yml`. Never directly write production Supabase or touch PG17 squash baseline. Post-deploy verify registered sources, active preview/staging, real streets→Geocodio, categories, images, duplicates and **actual** public `external_events` plus Home/Events/Map retrieval.
